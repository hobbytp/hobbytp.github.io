Phase B / 视觉语言样张

让工作保持形状的一张地图。

这是 Skills 视觉学习系统的交互预览样张，用来验证路线、调用类型、产物、决策和共享 primitive 的形状与标记是否能在不依赖颜色的条件下独立传递语义。

01 / 路线结构

一条路线，五次交接

路线是视觉焦点。每一步都有清晰角色，并且会携带一个产物进入下一步。

用户 / 工程 /grill-with-docs 澄清意图
产物 CONTEXT.md
+ ADR 共享语言
用户 / 工程 /to-spec 塑造行为
Agent / 工程 {tdd} 验证一个切片
Agent / 工程 {code-review} 检查规范与 spec
线性阅读顺序： 用户从 /grill-with-docs 开始，产出共享上下文（CONTEXT.md + ADR）。/to-spec 把澄清后的意图转成行为。Agent 使用 {tdd} 进行测试驱动开发，最后 {code-review} 审查最终变更。
02 / 共享层

地图下方的引擎

共享 primitive 是可复用的 discipline，不是路线上的另一个停靠点。五个 orchestrator 都通过它完成"挖掘决策分支"这件事。

共享 PRIMITIVE {grilling} 暴露决策分支

为以下五个 orchestrator 提供采访引擎：

/grill-me /grill-with-docs /triage /wayfinder /improve-codebase-architecture
03 / 阅读图例

形状承载语义

颜色加强含义，但即使不依赖颜色，形状、徽章和文字也足够清晰。

圆角矩形 用户调用的 orchestrator 或明确动作
[USER] badge + 蓝色边框
内侧边框矩形 模型调用的可复用 discipline
[AGENT] badge + 绿色双层边框
折角文档卡 在步骤之间传递的产物
[产物] badge + 右上折角
倾斜菱形 决策或路线分叉问题
[决策] badge + 黄色斜体框
双线六边形 共享 primitive：被多个 orchestrator 调用的可复用 discipline
[SHARED] badge + 灰蓝双线六边形
04 / 箭头词汇

四种箭头，四种关系

箭头传递交接方式，每种箭头只有一种意义。

实线箭头 正常交接或主路线流转
虚线箭头 可选绕路或支撑性 discipline
循环箭头 显式反馈或维护循环
分叉箭头 路线决策，每条分支标注条件
05 / 语义色板

克制的信号系统

bucket 标签区分工程与生产力。颜色描述工作流状态，不区分 bucket。
