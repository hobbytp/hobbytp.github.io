25 个技能的工作地图

为软件架构师和软件设计师设计的可视化学习路径。每张图回答一个实际问题，并标出对应 skill 在工作流中的位置。推荐从图 00 开始，按需深入。

── Phase C · 核心学习路径 ──────────────────

图 00 总览

我在工作的哪个阶段，应该走哪条路线？

七区操作地图，{grilling} 共享原语层，25 个技能的位置一目了然。

 图 01 功能流

一个模糊的功能需求如何变成可验证的小改动？

双泳道服务蓝图：人工决策层 + Agent 工作流，含 Triage 汇入点。

 图 02 入口选择

工作以不同形态出现时，我应该怎么做？

六条入口路线的决策树，避免"所有问题用同一个流程"的错误。

 图 03 架构决策

我正在解决哪种不确定性？

六层决策堆，从领域语言到验证行为，展示架构是决策序列而非一次性图纸。

 图 04 深度模块

设计师如何把行为转化成可维护的模块？

模块边界的反馈循环：行为 → 测试缝 → 小接口 → 实现 → 审查 → 精炼。

 图 05 原型边界

如何在不直接上线原型代码的情况下保留原型的决策？

双轨桥梁：原型轨 → 决策 → 生产轨，保留决策，丢弃一次性代码。

 图 06 跨会话规划

目标太大、决策不明时，如何跨多个会话推进？

Wayfinder 的决策票据循环：从模糊终点到清晰 spec，逐决策推进。

 图 07 调试

如何从"有什么东西坏了"走到有据可查的修复？

证据漏斗：症状逐步收窄为最小案例、假设、仪表化、修复、回归测试。

── Phase D · 维护与迁移视图 ──────────────────

图 08 代码库治理

架构团队如何防止 AI 驱动的代码库熵增？

可持续代码库循环：发布 → 摩擦观察 → 架构扫描 → 改进 → 再循环。

 图 09 上下文交接

哪些信息需要跨会话、跨人员或跨 Agent 传递？

三层上下文数据包：共享词汇 + 工作状态 + 交接摘要，按需持久化。

 图 10 方法迁移

同一套操作模型如何支持日常内容创作工作？

内容生产故事板：澄清 → 研究 → 草稿 → 挑战 → 发布 → 复盘。

 图 11 技能图集

可按阶段、调用类型、bucket 筛选的技能卡片图集，供随时查阅。
