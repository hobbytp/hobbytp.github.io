25 个技能各自在什么情况下使用，产出什么？

可按调用类型和 bucket 筛选的技能卡片图集。每张卡片包含：适用情境、执行动作、产出产物、下一步。

Bucket
区 1 · 定向 ── 路由与初始配置
用户 /ask-matt 工程
情境不知道从哪个技能开始，需要路由建议
动作询问当前情况，推荐最合适的技能
产物路由决策（下一步用哪个技能）
→ 见图 02 入口决策树
用户 /setup-matt-pocock-skills 工程
情境新仓库，尚未配置 Skills 工作约定
动作初始化 AGENTS.md、CONTEXT.md 模板
产物仓库配置文件
→ /grill-with-docs
区 2 · 澄清与接收 ── 澄清意图与接收外部工作
用户 /grill-with-docs 工程
情境一个新功能，领域术语不明确
动作结构化采访，建立共享词汇
产物CONTEXT.md + ADR
→ /to-spec 或 /to-tickets · 见图 01
用户 /grill-me 生产力
情境有一个想法，但受众或目标不清晰（内容或临时探索）
动作无状态结构化采访，澄清改变目标
产物内容简报（不持久化到仓库）
→ 图 10 内容流水线
用户 /triage 工程
情境外部提交的原始 bug 报告或功能请求
动作状态机分拣，赋予工单角色（需要更多信息 / 可执行 / 关闭）
产物分拣后的工单（含角色标记）
→ /grill-with-docs 或 /to-spec
Agent {domain-modeling} 工程
情境建立领域词汇时需要深度建模
动作提取实体、关系和不变量
产物领域模型文档
→ /grill-with-docs 更新 CONTEXT.md
区 3 · 决策 ── 收集证据与解决设计问题
Agent {prototype} 工程
情境存在可运行设计问题，实验比讨论便宜
动作构建可扔掉的原型，回答一个设计问题
产物benchmark 结果 / 观察结果（不是 production 代码）
→ 决策点 → /grill-with-docs 更新 ADR · 见图 05
Agent {research} 工程
情境问题可以通过文档或现有资料回答
动作查阅、汇总、对比证据
产物调查报告
→ /to-spec 或更新 ADR
用户 /wayfinder 工程
情境大型工作，架构决策尚不清晰，需多会话推进
动作映射决策依赖图，生成决策票据，逐决策推进
产物决策票据板 + 折叠后的 spec 前置条件
→ 折叠阈值后 → /grill-with-docs · 见图 06
用户 /to-questionnaire 生产力
情境需要从多人收集结构化反馈
动作将问题集转化为分发用问卷
产物问卷文档
→ 收集反馈 → /grill-me 分析
区 4 · 塑形 ── 分解工作与设计模块
用户 /to-spec 工程
情境意图已澄清，需要形式化行为规范
动作描述前置条件、后置条件、错误边界
产物spec（行为描述文档）
→ /to-tickets
用户 /to-tickets 工程
情境有 spec，需要分解为 agent-ready 工单
动作分解为带依赖边的独立工单
产物工单（含验收标准和依赖边）
→ /implement
Agent {codebase-design} 工程
情境需要设计模块边界或分析现有结构
动作评估内聚性、边界清晰度、依赖方向
产物ADR + 架构建议
→ /to-spec 或 /to-tickets · 见图 03
区 5 · 构建与验证 ── 实现代码与验证行为
用户 /implement 工程
情境有工单，开始构建
动作按工单逐切片构建，不偏离 spec
产物可工作的代码切片
→ {tdd} → {code-review}
Agent {tdd} 工程
情境在实现过程中，需要验证一个切片
动作红（失败测试）→ 绿（通过）→ 重构循环
产物通过的测试 + 经过重构的实现
→ {code-review} · 见图 04
Agent {diagnosing-bugs} 工程
情境难以复现的 bug 或生产回归
动作证据漏斗：症状→可复现→最小化→假设→修复
产物fix + 回归测试
→ 见图 07
Agent {code-review} 工程
情境实现完成，需要审查
动作双轴检查：规范合规 + spec 符合性
产物已审查的 diff（接口无扩张，行为符合 spec）
→ 合并 PR · 见图 04
区 6 · 维护 ── 持续改善架构质量
用户 /improve-codebase-architecture 工程
情境发现摩擦信号（测试变慢、重复代码、牵连修改）
动作架构扫描，识别高杠杆改进机会，选一个执行
产物改进机会排序 + 选定改进的工单
→ 进入图 01 功能流 · 见图 08
区 7 · 传递与支持 ── 保存上下文与协作
用户 /handoff 生产力
情境会话即将结束，需要保存状态供下次恢复
动作生成交接摘要（已完成 + 下一步 + 注意事项）
产物交接文档（层 3 上下文）
→ 见图 09
用户 /wait-what 生产力
情境读取了上下文后仍然不知道自己在哪
动作重建方向感，澄清当前工作的位置
产物重建的工作上下文
→ 继续中断的工作
用户 /teach 生产力
情境需要解释一个概念或系统给其他人
动作按受众调整深度，生成可分享的说明
产物说明文档或演示材料
→ 图 10 内容流水线
Agent {writing-for-agents} 生产力
情境需要为 Agent 写指令或 AGENTS.md
动作优化指令的可执行性，消除歧义
产物Agent-ready 指令文档
→ 见图 09
Agent {resolving-merge-conflicts} 工程
情境合并时出现冲突，需要语义感知解决
动作分析冲突意图，按语义而非行级别合并
产物已解决冲突的代码
→ {code-review}
Agent {wizard} 工程
情境需要引导用户完成多步配置或初始化流程
动作逐步引导，收集选项，生成配置
产物配置文件或初始化代码
→ /implement
共享原语层 ── 为多个 orchestrator 提供采访引擎
共享 {grilling} 生产力
情境orchestrator 需要挖掘未解决的决策分支
动作结构化采访引擎：识别决策分支，逐一深挖
产物已挖掘的决策分支（上层 orchestrator 消费）
被：/grill-me · /grill-with-docs · /triage · /wayfinder · /improve-codebase-architecture 调用
线性阅读顺序：按区域阅读（区 1→区 7），从定向到传递与支持。共享原语层的 {grilling} 被五个 orchestrator 使用。每张卡片的「下一步」指向图表编号或相邻技能，构成学习路径。
