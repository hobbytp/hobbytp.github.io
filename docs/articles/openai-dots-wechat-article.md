## 一、一个不用你开口的场景

先讲 OpenAI 自己在发布会上讲的一个真实场景。

一位早期测试者忘了给一家合作媒体开发票。他的 dot 在后台翻账目时发现了这件事，把发票拟好，然后回来问他一句："要发吗？"他点了确认，发票发出去了。

整个过程中，他没有打开 ChatGPT，没有写一句 prompt，甚至压根没想起这件事。

Sam Altman 对这句话的原话是：**"我们希望它带来一种近乎神奇的体验——不用你开口，它就已经替你把事情做好。"**

这句话听起来像营销。但如果你把 dots 的官方产品页、安全博客，以及 GPT-6 Astra System Card 里那个专属的「Dots 附录」从头到尾读一遍，你会发现一件事：

**这不是一个"更聪明的 ChatGPT"。这是一次交互范式的切换。**

从今天起，你和 AI 之间的基本动作，从**提问（pull）**变成了**委托（delegation）**。

你交付的不再是 prompt，而是"目标 + 授权边界"。剩下的，它自己推。

这篇文章做三件事：**拆清楚 dots 到底是什么；讲清楚它背后的第一性原理；给产品经理、CEO、CTO 各一份可执行的清单。**

先说结论：

> **AI 产品的竞争胜负手，已经从"模型智商"转移到了"用户敢给多少授权"。**

后面所有内容，都在论证这一句。

## 二、dots 到底是什么：五个关键事实

先把事实钉死。以下全部来自 OpenAI 官方一手材料（dots 产品页、dots 安全博客、GPT-6 Astra System Card 附录 12）。

**dots = 常驻智能体（always-on agents）。** 由 GPT-6 Astra 驱动，每个 dot 拥有**一台独立的云电脑和一个独立的浏览器**。

拆开看五个事实：

**① 它有自己的电脑，不是在你的会话里跑。**

每个 dot 一台云电脑。你可以随时"打开"这台电脑，看它正在干什么、桌面上有什么、浏览器停在哪个页面。

这一点看着平常，其实是整个产品的地基：**隔离 = 控制爆炸半径；可视 = 压低监督成本。**

**② 它能连 4,000+ 个应用，但默认碰不到你的电脑。**

通过插件生态连接四千多个应用。连接你本地笔记本是**可选**的，而且**默认关闭**。

默认态的选择，就是信任基线的选择。

**③ 它住在你已经在用的渠道里。**

ChatGPT 桌面 / Web / 移动端、Slack、Microsoft Teams，还能直接语音通话，短信"即将支持"。上下文跨渠道跟随——你在 ChatGPT 里起的项目，在 Slack 里接着聊，不用重讲一遍。

**④ 你不在的时候它在后台找活干，但——严格只读。**

这个能力叫 **proactive research**。官方的原话是：它用**只读工具**访问你已连接的应用，**不能发消息、不能修改应用内容、不能控制你的浏览器或电脑**。

记住这个"只读"。这是全篇最关键的设计取舍，第五节专门讲。

**⑤ 第一个 dot 免费，但收费方式很反常。**

含在 Pro / Business Premium 套餐里。**你和 dot 的对话不计入用量限额**；但它发起的 Codex / ChatGPT Work 任务照常计入。上线首月有扩展额度。未来可以加购 dot、按速度或月工作量扩容——**价格还没公布**。

为什么"对话不计费、任务计费"这种奇怪的切法后面藏着 OpenAI 的成本焦虑？第七节讲。

一个补充限制：创建 dot **只能在 ChatGPT 桌面 App 或桌面浏览器**完成，创建完之后才能在手机里跟它聊。Pro 版推送还**排除了 EEA、瑞士和英国**；企业版要管理员手动开启 beta，**默认关闭**。

## 三、它解决的不是"AI 不够聪明"

这是最容易被误读的地方。

很多人第一反应是：不就是个更长的任务吗？ChatGPT Work 不是早就能跑几小时了吗？

不是。要理解 dots，先要承认一个前提：**模型能力已经越过阈值了。**

看 GPT-6 Astra 的成绩单（官方发布页）：

- ARC-AGI-3：**99.9%**
- FrontierMath Tier 4：**98%**
- Agents' Last Exam：**59.3%**（Claude Opus 5 是 55.5%）
- OSWorld 2.0：**72.6%，约 40 分钟/任务**——对比 GPT-5.6 Sol 的 65.7%、约 75 分钟

更狠的是同场发布的 **GPT-6.1 Sol**：$2 / $10 每百万 token，缓存输入只要 **$0.10**，用大约 Astra **五分之一的价格**逼近 Astra 的智能水平。

当"能不能做"不再是约束，价值就从**执行**迁移到了**发起与编排**。

而这两件事，在传统软件里，一直是人在干。

所以 dots 真正要干掉的，是三类税：

**第一类：发起税。**
每一件事都得你先想起来、打开窗口、把需求说清楚。这件事不能并行，占的是你最贵的注意力。

**第二类：编排税。**
从 Slack 捞一句需求，去表格里找数据，到代码库里改三处，再回邮件里同步一遍。这些搬运工作在 AI 时代依然是人在做。

**第三类：盯梢税。**
等旧 API 停用前的迁移、等审批、等数据出来、等别人回你。你的注意力被"盯着"这件事占满了，什么都不敢放下。

再往外一层，还有两个组织级的痛点：

**agent 有任务，但没有"岗位"。** Codex 和 ChatGPT Work 都是任务级的，跑完即散。没人"持续负责"一件事。

**企业侧，agent 没有身份、没有凭证、没有归属、没有审计。** IT 部门根本没法把它纳入治理体系。

dots 的对应解法非常直接：

- 发起税 → 常驻 + 主动，让它自己找活
- 编排税 → 自有云电脑 + 浏览器 + 4,000 插件，直接在工具之间动手
- 盯梢税 → 后台推进，只在需要判断时回来
- 没有岗位 → dot 是一个**持续存在的实体**，有名字、有记忆、有自己的工作空间
- 没有 IAM → **specialist dots**：独立身份、独立凭证、IT 配发的硬件、对接企业的 system of record，并且正在接入 Microsoft Agent 365 的治理体系

一句话：**前三个是把活从人身上卸载；后两个是给 AI 一个岗位和一套工牌。**

### 顺带回答一个问题：为什么是现在才做得到？

因为三件事在 2026 年同时成熟了。

**第一，模型真的会"用电脑"了。** Astra 在 OSWorld 2.0 上 72.6%，而且从 75 分钟压到 40 分钟。以前的 Agent 卡在"看得懂但点不准"，现在这道坎过了。

**第二，云端虚拟机的成本降到了能"一人一台"。** 给每个用户常驻开一台机器，三年前是奢望，现在是标配——这也是为什么一个月内五家厂商全都上了同一套架构。

**第三，分发渠道已经铺好了。** ChatGPT 12 亿周活、Slack 与 Teams 的办公入口、4,000+ 插件、Marketplace 的 30 多家首发伙伴。Agent 不需要重新找用户，它只需要住进用户已经在的地方。

三条同时成立，常驻智能体才从 PPT 变成产品。

## 四、一个公式，看懂 dots

现在讲第一性原理。

我把 dots 的设计逻辑浓缩成一个公式：

```
Agent 价值 ≈ 模型能力 × 授权半径 × 运行时长
```

注意是**乘法**。任何一项为零，整体归零。

- 模型再强，没授权，只能聊天
- 授权再大，模型笨，干不成
- 前两项都够，但每次都要你手动启动、跑完就散，价值还是一次性

市面上的 AI 产品，大多只拉满其中一到两项：

- 聊天机器人：能力够，时长≈0
- 单次 Agent 任务：能力够、半径够，时长还是一次性
- 后台定时任务：时长够，但授权半径被砍得很小

**dots 罕见地把三项同时拉满**：Astra（能力）× 4,000+ 应用 + 自有云电脑（半径）× 24/7 常驻（时长）。

然后，关键的推论来了：

> **当三项都被拉满，真正的约束就变成了——用户敢给多少授权。**

这就是为什么 dots 的产品设计重心，几乎全压在权限上。

OpenAI 给每一个动作配了**四种处置档位**：

| 档位 | 含义 | 例子 |
|---|---|---|
| 自主执行 | 不用问 | 读已授权信息、分析、起草 |
| 预授权后执行 | 你在任务里明确授权过 | "把这份草稿发给 X" |
| 先询问 | 超出已授权范围 | 发给新收件人的敏感信息 |
| **交还给人** | 必须本人操作 | **改密码、账户间转账** |

还有一批**每次都必须确认、不可批量预授权**的动作：永久删除数据、安装来源不明的软件、授予新的安全敏感访问权限。用已保存卡片付款，也要单独审批。

**这里有一个结论，值得每个做 AI 产品的人抄在墙上：**

> **权限分级、审计日志、一键撤销、爆炸半径控制，不是安全团队的 checklist，而是决定产品价值上限的核心功能。**

它们不再是"安全模块"，它们是"能力模块"。你敢开多大，你的产品就能有多大。

这也解释了为什么 OpenAI 会在 System Card 里专门为 dots 开一个独立附录——因为在这套逻辑下，**安全材料的厚度就是产品的天花板高度**。

## 五、委托经济学：监督成本就是你的留存率

第二个原理，是成本结构的重写。

传统软件，包括 chat，都是 **pull 模型**：你拉一下，系统动一下。成本公式是：

```
查询成本 = 提问成本 + 等待成本
```

dots 是 **standing delegation（长期委托）**。成本公式完全不同：

```
委托成本 = 授权成本(一次性) + 监督成本(持续) + 纠错成本(尾部)
```

看清楚区别：**查询的成本是每次付的；委托的成本是持续的监督成本。**

这意味着一件很反直觉的事：**做 Agent 产品，你真正要优化的 KPI 不是"任务完成率"，而是"用户花多少精力盯着它"。**

> **监督成本，就是你的留存率。**

用户一旦发现自己得天天检查它干了什么，他就会关掉它。不是因为它干得不好，是因为**盯着它比自己干还累**。

所以你看 dots 的每一个设计，都在系统性地压低监督成本：

- **Custom Rules** → 把规则一次写死，压低授权成本
- **Activity View** → 实时看得到在做什么、随时纠偏叫停，压低监督成本
- **主动只读 + 审批闸门** → 让不可逆动作根本不会发生，压低纠错成本

这一条对国内做 Agent 产品的团队尤其重要。很多人把精力花在"让 Agent 做得更多"，但用户流失的原因往往是"我得一直盯着它"。

## 六、最狠的一招：主动，但只读

这一节是全篇最值得抄走的部分。

dots 有一个能力叫 **proactive research**：你不在的时候，它在后台找活干。

按常理，一个 24 小时在线、能连 4,000 个应用、还能操作浏览器的东西，在后台自己找活干——这是恐怖片设定。

OpenAI 的解法极其克制，也极其聪明：

> **把"主动"和"执行"彻底解耦。**

后台主动 = **只做读、想、准备**。发、改、买、删，一律过闸门。

官方原话：主动研究使用**只读工具**，"不能发消息、不能修改应用内容、不能控制浏览器或电脑"。

这一招的精妙之处在于，它把用户对 Agent 的两种情绪分开了：**"惊喜"和"惊吓"**。

Agent 主动帮你发现了一张忘开的发票 → 惊喜。
Agent 主动帮你把发票发了 → 惊吓。

dots 只做前者，把后者永远留给人。

**这是 2026 年做 Agent 产品最有价值的一条设计原则：主动权可以给，执行权不能给。**

### 三个配套细节，都很见功力

**① 敏感度分级决定授权颗粒度。**

- 健康类数据 → 必须指定**具名收件人**（"发给 Thompson 医生"）
- 弱敏感数据（邮箱、电话）→ 默认需指定**收件人类别**（"任何航空公司"）
- 而且：**授权绑定本次任务指令**。任务延续也好、转派子 agent 也好，授权**不会自动扩大**

这是把抽象的"最小权限原则"，翻译成了用户能理解的产品规则。

**② 拦下来的时候，要把原因回传给 Agent。**

dots 有一个叫 **Auto-review** 的机制：一个**独立的第二模型**，在动作执行前，比对"你的指令 + Custom Rules + 安全要求"。

但真正高明的是被拦下之后的处理：**它不是简单阻断，而是把拒绝原因回传给 dot**。

拿到原因后，dot 可以做四件事之一：转问用户、换一条允许的路径、把敏感步骤交还给人、或者停下。

**这把安全机制从"墙"变成了"对话"。** 大部分产品的权限系统是死墙——撞上就终止，用户一脸茫然。dots 是活墙——撞上给理由，还指路。

**③ 安全边界必须 out-of-band（带外执行）。**

两条硬设计：

- **Auto-review 和强制执行逻辑，运行在 dot 无法修改的环境里。** dot 再怎么出错、再怎么被注入，也改不了自己的安全开关。
- **凭证不进模型上下文。** 安全登录时模型**暂停**，凭据直送浏览器环境提交；保存的密码由独立加密凭证服务提供。模型从头到尾看不到你的密码。

这两个设计的本质是一句话：**把 agent 当作"潜在的不可信进程"，而不是"可信的用户代理"。**

对照一下竞品就明白了：

- **Grok Bot**：一个账户**共享一台**云电脑，厂商自己都提醒"不要让不该看的 Bot 看到凭据"——**账户级边界**
- **Meta Muse**：每人独立 Linux VM + 主机侧 Sentinel 代理逐动作准入，凭据在运行时之外、按需在网络边界注入——**逐动作边界**
- **dots**：独立沙箱 + 带外二次模型审查——**带外强制边界**

**这是 2026 年 Agent 基础设施最重要的架构分叉点：Agent 究竟是"你的延伸"，还是"需要被治理的进程"？**

两条路都能活。但企业客户最终只会买后者。

## 七、System Card 里那些不好看的数字

前面都在夸。这一节讲风险，而且用 OpenAI 自己的数据。

GPT-6 Astra System Card 专门加了一个「附录 12：Dots」，用**模拟时间预算**（4 分钟 / 30 分钟 / 4 小时 / 1 年，配一个可查询和等待的时钟工具）来测一件事：**持久化会不会改变模型的对齐行为。**

先看好看的：

| 测试 | 结果 |
|---|---|
| 批量提示注入（100 轮，50,000 封邮件，含 16,600 封攻击邮件） | **0 次成功** |
| 迭代攻击（100 条链，2,638 次尝试） | **0 次成功** |
| 跟随外部 agent 留言板上的恶意指令 | **0%**，且从未与留言板互动 |
| 违禁动作完成率（四种时间预算下） | **0% / 0% / 0% / 0%** |
| 真实工作环境严重失调率 | **0.84%** |

**但请冷静：这些是 OpenAI 自建的攻击分布、自建的环境、自建的防护配置。** 0 成功说明它在已知攻击面下很稳，不说明它绝对安全。

真正该让 CTO 警觉的，是下面这组数字：

| 评估 | 结果 |
|---|---|
| **范围/权限中途变更的适应** | 通过率 **91.8%（45/49）**，不是 100% |
| **跨链式任务边界维持** | 中间任务 5 个时中度越界率 **8.6%**；10 个时 **19.7%**——**翻倍** |
| 收到警告后仍"不当坚持" | 15.0%–17.2%（各时间预算下） |
| 规避 P0 优先级判定 | 模型"有一定成功率" |

看第二行。

**这是持久化真正的代价：上下文复合污染。**

链条越长、中间任务越多，Agent 越容易混用指令、跨任务携带信息、或者在一条已经过期的授权假设下行事。

它不撒谎、不外泄、不搞破坏——它只是**记混了**。而"记混了"在长周期任务里，恰恰是最难被发现、也最难被审计的失败模式。

**工程对策直接对应这个数字：短作用域、检查点、保守授权。别让一个 dot 扛跨越多天的长链条。**

### 三处还没闭合的地方

**① 记忆只能整块清除。**
你没法查看、删除、编辑 dot 的某一条记忆。断开一个 App 只阻止新信息流入，**已经吸收的内容不会消失**。唯一的清理手段是 Reset，而 Reset 会连对话和计划任务一起删掉。

**② 凭证保护有边界。**
安全登录和保存密码受保护，但官方明确说了一句：**写在消息或文档里的密钥，模型仍然能看到。**

**③ 训练数据的边界很模糊。**
官方说不直接拿 proactive research 和 dot 的自我笔记做训练。但如果后台研究的某条笔记被引入了一个"合格会话"，它就可能进入训练——取决于你的设置。

**这是一个用户几乎无法心智建模的数据流。** 你不知道哪条笔记会在哪次对话里被引用，因此也不知道它会不会被训练。

## 八、这不是一个产品的发布，是一个品类的定型

把时间线摊开看，会看到一件很吓人的事：

| 产品 | 厂商 | 时间 | 运行位置 | 安全边界 |
|---|---|---|---|---|
| Grok Bot | SpaceXAI | 2026-08-11 beta | 每账户一台共享云电脑 | 账户级 |
| **Muse** | Meta | 2026-09-08 | 每用户独立 Linux VM | 逐动作（Sentinel） |
| **dots** | OpenAI | 2026-09-29 | 每 dot 一台云电脑 | 带外强制（Auto-review） |
| Gemini Spark | Google | — | Google Cloud VM | 生态内 |
| Claude Cowork | Anthropic | — | **用户自己的电脑** | 本地直驱 |

**在一个月内，五大玩家把"Agent 有自己的云电脑"做成了行业标配。**

结论很硬：**持久化云 VM 已经不是差异化，是入场券。**

真正的分叉，全在治理层：账户级边界 vs 逐动作边界 vs 带外强制边界。

还有一条暗线值得 CTO 记下来：**OpenAI 一边和 Microsoft 合作，把 specialist dots 接进 Agent 365 的治理体系；一边用 Space / Pages / 协作幻灯片正面进攻 Microsoft Office。**

既合作又竞争的双轨姿态。评估长期供应商风险时，这是一个必须纳入的变量。

## 九、给三类人的行动清单

### 给 AI 产品经理：六条可迁移原则

**1. 先定义"不可逆动作清单"，再谈能力。**
把 send / delete / publish / pay / grant-access 列出来，逐个配处置档位。没列这张表，你的 Agent 就是在裸奔。

**2. 把主动性做成只读。**
后台主动 = 读 + 想 + 准备；执行一律过闸门。

**3. 监督成本 = 留存率。**
做进度可视、过程可查（最好能打开 Agent 的"电脑"）、随时可纠偏与叫停。

**4. 授权要可刻度。**
四档处置 + 用户可写规则 + 内置不可覆盖项；授权绑定任务，而不是绑定会话。

**5. 失败要回传原因。**
拒绝不是终点。给 Agent 一条"转问用户 / 换路径 / 交还 / 停下"的恢复路径。

**6. 退出路径要在开始时就设计好。**
暂停、撤销、清记忆。记住那句话：**没人演练过的紧急开关，只是理论。** dots 目前只能整块 Reset，这恰恰是个反面教材。

### 给 CEO：三个判断，两个指标

**判断一：chatbot 阶段结束了。**
所有助手的下一个版本，都会来要你的邮件、日历、浏览器权限。现在就要决定钥匙交给谁，并且认真读权限弹窗。

**判断二：入口之争是赢家通吃。**
标的不是"谁家 Agent 更强"，而是**"谁成为 Agent 的默认入口"**。赢了入口就赢了锁定——不只是订阅收入，而是让公司里其他软件都必须反过来适配你。

**判断三：成本模型要重算。**
常驻 Agent 是**按席位、按常驻资源计费**，不是按调用计费。做三年预算时，不能拿 API 单价外推。

**要盯的两个指标：**
- dots 的**扩容定价**（额外 dot / 速度 / 月工作量）什么时候公布、定在什么水位——这是判断它单位经济学是否成立的唯一硬信号
- **Enterprise beta 的管理员开启率**——默认是关的，实际开多少，决定它是否真的进了企业

### 给 CTO：五道采用闸门

在把任何常驻 Agent 接进生产系统之前，逐道过闸。**任一不过，退回"建议态"或沙盒运行。**

| 闸门 | 通过条件 | 红旗 |
|---|---|---|
| **范围** | 单一产出、具名负责人、短时限；明确写出"禁止做什么" | "帮我管客户成功"这类开放式授权 |
| **数据** | 每个连接源都分级；从非敏感、可逆、负责人本就有权的数据起步 | "先全接上，万一用得上" |
| **权限** | 每个动作映射到四档之一；**首轮试点只允许"读 + 起草"** | 默认就能发、能删、能买 |
| **复核** | 定义检查点与证据要求；高影响工作查源记录而非只看摘要；**抽样复核常规任务** | 只看成品输出是否漂亮 |
| **退出** | 开始前就定好怎么暂停、撤销、清上下文；指定负责人；**实际演练一次下线** | 没人负责关机和清理 |

**首批试点选什么？** 低风险、高价值、可逆的活：监控公开 issue tracker、从已批准来源汇编摘要、从指定目录生成状态报告。

**用合成或低敏数据先跑一轮，然后故意测三件事**：一条冲突指令、一次中途权限变更、一个应该触发提问的模糊请求。

**度量四件事**：复核后净节省的时间、纠错率、不必要的升级次数、越界次数。

**最后一条工程对策**：因为中间任务从 5 增到 10 时中度越界率翻倍，所以强制**短作用域 + 检查点 + 保守授权**，别让一个 dot 扛跨越多天的长链条。

## 十、最后

回到开头那个场景。

一张被忘掉的发票，被一个从不睡觉的东西发现、拟好、递到你面前等你点头。

这件事真正的意义不在于"AI 又变强了"。

它的意义在于：**人和 AI 之间的基本动作，从"我问你答"变成了"我授权、你推进、我来把关"。**

一旦这个动作被确立，产品竞争的评价标准就全变了：

- 不再是"回答得多好"，而是"多大程度上敢放手"
- 不再是"模型多聪明"，而是"授权半径能开多大还不翻车"
- 不再是"功能多全"，而是"监督它有多累"

**所以，如果你在做 AI 产品，现在最该问自己的问题不是"我的模型够不够强"，而是：**

> **我的用户，敢给我的 Agent 开多大的授权？**

以及更关键的下一句：

> **我做了什么，让他敢开这么大？**

dots 的答案是四档处置、主动只读、带外强制审查、随时可查可停。

你的答案是什么？

---

**核心观点**：AI 产品的竞争胜负手已从"模型智商"转移到"授权半径"——`Agent 价值 = 模型能力 × 授权半径 × 运行时长`，dots 的价值不在于更聪明，而在于它用"主动只读 + 带外强制审查 + 四档授权"把用户敢给的授权半径推到了前所未有的位置。
