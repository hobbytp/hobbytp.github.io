# ChatGPT Dots 深度研究报告

**——从痛点、第一性原理到设计逻辑，写给 AI 软件产品经理与 CEO/CTO**

- 研究对象：OpenAI **dots**（常驻智能体），2026-09-29 DevDay 2026 发布
- 报告日期：2026-10-04
- 证据口径：以 OpenAI 官方一手材料（产品页、安全博客、GPT-6 Astra System Card 附录 12「Dots」）为主干，媒体二手报道仅用于竞争与市场面，并单独标注可信度

---

## 0. 结论先行（Executive Summary）

1. **dots 不是"更强的 ChatGPT"，而是交互范式的切换：从 pull（人发起请求）转向 delegation（人授予长期委托）。** 用户交付的是**目标 + 授权边界**，不是 prompt；agent 在两次对话之间继续推进，只在需要判断与授权时回来找人。

2. **它解决的真正痛点不是"AI 不够聪明"，而是三类税：发起税、编排税、注意力税。** 模型能力已过阈值（GPT-6 Astra 在 ARC-AGI-3 99.9%、OSWorld 2.0 72.6%），瓶颈转移到"谁先想起来做"和"谁来把跨系统的活串起来"。

3. **第一性原理可以浓缩成一句公式：`Agent 价值 = 模型能力 × 授权半径 × 运行时长`。** dots 是唯一一个把三项同时拉满的产品形态——Astra（能力）× 4,000+ 应用 + 独立云电脑（半径）× 24/7 常驻（时长）。这也意味着**产品竞争的胜负手从"模型智商"转移到"你敢给它多少授权"**，权限、审计、可撤销性因此成为核心功能而非附属安全模块。

4. **最关键的设计取舍是"主动 = 只读"：proactive research 被硬性限制为只读工具，不能发消息、不能改内容、不能控浏览器。** 这是全篇最值得产品经理抄走的一招：把"主动性"和"执行权"解耦，用主动只读换取用户的心理安全感，把不可逆动作留在审批闸门后。

5. **治理架构采用 out-of-band enforcement：Auto-review 与安全监控运行在 dot 无法修改的环境里，凭证通过独立加密凭证服务注入、不进模型上下文。** 这是把 agent 当作"潜在不可信进程"来设计，而不是当作"可信的用户代理"——与 Grok Bot（账户级共享 VM）形成鲜明对比，与 Meta Muse（Sentinel 逐动作准入）同属"安全优先"阵营。

6. **商业上的最大未验证假设是单位经济学：每个 dot 一台常驻云电脑，成本结构从"按请求计费"变成"按席位常驻算力计费"。** 目前第一个 dot 免费、对话不计入限额，但 Codex / ChatGPT Work 任务计入；额外 dot 与扩容定价尚未公布。CEO 应把"dots 的边际毛利率"列为观察指标，而不是把它当作已成立的商业模型。

7. **给 CTO 的落地建议：采用五道闸门（范围 / 数据 / 权限 / 复核 / 退出），任一不过则退回"建议态"或沙盒。** System Card 自己给出的关键数字支持这个保守姿态：长链任务中间任务数从 5 增到 10，中度越界标记率从 **8.6% 翻倍到 19.7%**；权限中途变更的适应通过率为 **91.8%（45/49）**，不是 100%。

## 1. 事实基线：dots 到底是什么

### 1.1 官方定义与能力边界

出处：OpenAI《Introducing dots》产品页（一手）

| 维度 | 事实 |
|---|---|
| 定位 | "remarkably capable, always-on agents built to handle everything" |
| 模型 | GPT-6 Astra |
| 运行时 | **每个 dot 一台独立云电脑 + 独立浏览器**；可随时打开这台电脑检查它在做什么 |
| 本地接入 | 可选；**默认关闭**；接入后可读写本地文件、跑本地技能、在云浏览器被拦时回退到本地浏览器 |
| 应用连接 | 通过插件生态连接 **4,000+ 应用** |
| 触达渠道 | ChatGPT（桌面 / Web / 移动）、Slack、Microsoft Teams、语音通话；短信 "coming soon" |
| 上下文 | 跨渠道携带，在 Slack 里继续 ChatGPT 里的项目无需重述 |
| 主动能力 | **proactive research**：人不在时后台找活干，**仅限只读工具**，不能发消息、不能改应用内容、不能控制浏览器或电脑 |
| 身份 | 可命名、可定制形象；官方设想未来是"多个 dot 组成团队" |
| 创建入口 | **仅** ChatGPT 桌面 App 或桌面浏览器；创建后可在移动端对话 |
| 可用性 | Pro / Business Premium（合规市场）；Enterprise / Edu / Healthcare 由管理员开启的 beta，**默认关闭** |
| 地域 | Pro 版推送**排除 EEA、瑞士、英国**；Business Premium 覆盖所有支持的 ChatGPT 区域（二手，源自多家媒体一致报道） |
| 计费 | 第一个 dot 免费含在 Pro / Business Premium；**与 dot 的对话不计入用量限额**；它发起的 Codex / ChatGPT Work 任务照常计入；上线首月有扩展额度；未来可加购 dot、按速度或月工作量扩容（定价未公布） |

### 1.2 权限与动作分级（官方安全博客，一手）

dots 把每一个动作落到四种处置之一：

| 处置 | 含义 | 典型例子 |
|---|---|---|
| 自主执行 | 不用问 | 读取已授权信息、分析、在会话内起草 |
| 预授权后执行 | 你在任务里已明确授权 | "把这份草稿发给 X" |
| 先询问 | 超出已授权范围 | 向新收件人发敏感信息 |
| **交还给人（handoff）** | 必须本人操作，模型只能做周边工作 | **改密码、账户间转账** |

**每次都必须确认**（不可批量预授权）：永久删除数据、安装或运行来源不明的软件、授予新的安全敏感访问权限。**已保存卡片的购买需审批。**

**信息共享的敏感度分级**（这是很有产品感的一处设计）：
- 健康类数据 → 必须指定**具名收件人**（"把这个发给 Thompson 医生"）
- 弱敏感个人数据（邮箱、电话）→ 默认需指定**收件人类别**（"任何航空公司"）
- 用户可用 Custom Rules 放宽弱敏感类别（如"任何在线表单"）
- 授权**绑定于本次任务指令**，后续延续或转派子 agent 都不会扩大授权

### 1.3 安全架构的四层（一手）

1. **模型层**：Astra 被训练成理解意图、守住任务边界、在答案会影响行为时主动提问；拒绝生物 / 网络滥用类请求。
2. **工作空间层**：每 dot 独立云电脑，沙箱限制代码与工具；用户云环境彼此隔离；**执行代码的环境与"协调工作 + 执行关键防护"的系统相互分离**，dot 再出错也改不了自己的安全开关。
3. **凭证层**：安全登录时**模型暂停**，凭据直送浏览器环境提交，不进模型上下文；保存的密码由专用加密凭证服务提供，同样不暴露给模型。**但官方明确留了一个口子**：写在消息或文档里的密钥，**模型仍能看到**。
4. **动作层**：**Auto-review**——独立的第二模型，在动作执行前比对"你的指令 + Custom Rules + 安全要求"，通过才执行，被拦则把原因回传给 dot（dot 可以转问你、换一条允许的路径、把敏感步骤交还给你、或停下）。

另外：**Activity View** 可实时查看进行中与已委派任务、随时纠偏或叫停；**Reset** 会删除 dot 的对话、记忆与计划任务——**这是目前清除其上下文的唯一方式**（断开一个 App 只阻止新信息流入，已吸收的信息不会消失）。

### 1.4 System Card 附录 12「Dots」的关键实测数字（一手，最有价值的部分）

> 注：OpenAI 用**模拟时间预算**（4 分钟 / 30 分钟 / 4 小时 / 1 年 + 一个可查询与等待的时钟工具）来专门测"持久化会不会改变对齐行为"。这是理解 dots 风险的硬证据。

## 2. 痛点解剖：dots 到底在解决什么问题

把"AI 助手不好用"拆成可定价的成本项，dots 每一项都有对应解法：

| # | 痛点 | 成本性质 | dots 的解法 |
|---|---|---|---|
| 1 | **发起税**：每个任务都要人先想起来、打开窗口、写清楚需求 | 人的注意力，不可并行 | 常驻 + 主动：dot 自己找活，把"想起来的成本"从人转移到 agent |
| 2 | **冷启动税**：每次都要重新交代背景、偏好、标准 | 重复的上下文搬运 | 持久上下文 + 从反馈中学习偏好，跨会话、跨渠道延续 |
| 3 | **编排税**：跨 Slack / 邮件 / 表格 / 代码库搬运与对齐 | 人的低价值时间 | 自有云电脑 + 浏览器 + 4,000+ 插件，直接在工具之间动手 |
| 4 | **盯梢税**：等 API 停用、等审批、等数据出来、等别人回 | 人的注意力被占住 | 后台持续推进，只在需要判断时回来 |
| 5 | **并行度天花板**：一个人同时只能推进有限几件事 | 吞吐 | 一个 dot 可同时跑多个项目，人只管加需求 |
| 6 | **agent 有任务但没有"岗位"**：Codex / ChatGPT Work 是任务级，跑完即散 | 组织层面的责任真空 | dot 是**持续负责某件事的实体**，有名字、有记忆、有工作空间 |
| 7 | **企业侧：agent 没有身份、凭证、归属、审计** | 合规与 IT 治理成本 | **specialist dots**：独立身份、独立凭证、IT 配发的硬件、对接系统 of record；对接 Microsoft Agent 365 的治理与安全控制 |
| 8 | **信任缺口**：常驻 + 高权限 = 一旦出错代价远超聊天 | 风险溢价 | 四档动作策略 + Custom Rules + out-of-band Auto-review + Activity View + 可 Reset |

**一句话概括**：前五个痛点是**个人生产力**层面的，dots 的答案是"把发起、编排、盯梢从人身上卸载"；第 6、7 个是**组织形态**层面的，dots 的答案是"给 agent 一个岗位和一套 IAM"；第 8 个是**采纳门槛**，dots 的答案是"把不可逆动作全部留在审批闸门后"。

## 3. 第一性原理：七个根本判断

### P1 · 智能的边际成本塌缩后，稀缺的是"发起"而不是"能力"

GPT-6.1 Sol 以 Astra **1/5 的价格**提供接近 Astra 的智能；缓存输入 $0.10/百万（比标准输入便宜 95%）。当"能不能做"不再是约束，价值就从**执行**迁移到**发起与编排**——而这两件事在传统软件里一直是人在做。dots 的产品动作（常驻、主动、跨渠道）全部指向"替你发起"。

**推论**：任何以"更聪明的回答"为卖点的 AI 产品，其差异化窗口正在关闭；下一个窗口是**"替用户发起的正确率"**。

### P2 · 交互原子单位从「请求-响应」变成「委托-审查」

传统软件（包括 chat）都是 **pull 模型**：人拉一下，系统动一下。dots 是 **standing delegation**：人设定目标与边界，系统按事件驱动推进。

委托的经济学成本结构与查询完全不同：

```
查询成本   = 提问成本 + 等待成本
委托成本   = 授权成本(一次性) + 监督成本(持续) + 纠错成本(尾部)
```

dots 的每一个设计——Custom Rules（压低授权成本）、Activity View 与进度回传（压低监督成本）、只读主动 + 审批闸门（压低纠错成本）——都在系统性压低**监督成本**。产品经理做 agent 产品时，**监督成本就是你的留存率**。

### P3 · 上下文是资产，必须挂在"身份"上而不是"会话"上

每次对话重建上下文 = 每次对人征收一次注意力税。要让上下文可复用，最小的承载结构不是"历史记录"，而是**一个持续存在的实体**：有名字、有记忆、有自己的工作空间、有自己的偏好演化。这就是 dots 为什么被设计成"人格化的持久实体"（可命名、有形象、可语音通话），而不是一个"后台任务队列"。

**拟人化不是卖萌，是授权的心理脚手架**——人只会对"某个可归因的对象"授予长期权限，不会对"一个功能开关"授予长期权限。

### P4 · 能力上限由「授权半径」决定，不是由模型智商决定

```
Agent 价值 ≈ 模型能力 × 授权半径 × 运行时长
```

任何一项为零，整体为零。dots 罕见地同时拉升三项：Astra（能力）× 4,000+ 应用 + 独立云电脑（半径）× 24/7（时长）。

**推论**：当三项都被拉满，**真正的约束变成"用户敢给多少授权"**。所以权限分级、审计日志、一键撤销、爆炸半径控制，不是安全团队的 checklist，而是**决定产品价值上限的核心功能**。这也解释了为什么 OpenAI 在 dots 上把安全材料做到了 System Card 独立附录的规格。

### P5 · 安全边界必须 out-of-band：把 agent 当"潜在不可信进程"，而非"可信用户代理"

dots 的两条硬设计：
- Auto-review 与强制执行逻辑跑在 **dot 无法修改的环境**里，dot 不能关掉任何必需检查；
- 凭证走独立加密凭证服务，**注入浏览器而不进模型上下文**。

对照竞品：Grok Bot 给一个账户**一台共享云电脑**，xAI 自己警告"不要让不该看到的 Bot 看到凭据"（**账户级边界**）；Meta Muse 给每人独立 Linux VM + **Sentinel 主机侧准入代理**，凭据在运行时外、按需在网络边界注入（**逐动作边界**）；dots 落在"独立沙箱 + out-of-band 二次模型审查"这条路上。

**这是 2026 年 agent 基础设施最重要的架构分叉点**：agent 究竟是"你的延伸"（共享状态优先）还是"需要被治理的进程"（权限刚性优先）？两条路都能成立，但**企业客户最终只会买后者**。

### P6 · 分发比能力更稀缺

dots 不是孤立功能，而是被塞进已存在的分发面：ChatGPT **12 亿周活用户**（DevDay 官方口径）、Slack / Teams 办公入口、4,000+ 插件、OpenAI Marketplace（30+ 首发伙伴）、Sign in with ChatGPT（16 家合作方可用套餐额度）。

**CEO 视角**：这场仗的标的不是"谁家 agent 更强"，而是**"谁成为 agent 的默认入口"**——赢了入口就赢了锁定：不只是订阅收入，而是让公司里其他所有软件都必须来接你。

### P7 · 成本结构从「按请求计费」转向「按席位常驻算力计费」

每个 dot 一台云电脑、24/7 在线。这与"生成一次回答"是完全不同的成本曲线。OpenAI 的处理方式很值得玩味：

- 与 dot **对话**不计入限额（把"沟通"变成零边际成本感知，鼓励高频委托）
- dot 发起的 **Codex / ChatGPT Work 任务**照常计入（把真实算力消耗留在计量里）
- 第一个 dot 免费（先建习惯）、首月扩展额度（先给甜头）、未来按速度与月工作量扩容（后收费）

**这是一套典型的"先固化行为、后 monetize 容量"的定价路径。** CTO 做预算时应按**常驻资源**而非按 API 调用建模。

## 4. 设计逻辑拆解：九个层次

| 层 | 设计决策 | 背后的逻辑 |
|---|---|---|
| **形态层** | 可命名、有形象、可语音通话 | 拟人化 = 降低长期授权的心理门槛（P3） |
| **运行时层** | 每 dot 一台独立云电脑 + 浏览器，可随时打开查看 | 隔离 = 控制爆炸半径；可视化 = 压低监督成本 |
| **本地接入层** | 可选，**默认关闭** | 默认态决定信任基线；把最高风险面设为 opt-in |
| **权限层** | 四档处置（自主 / 预授权 / 询问 / 交还）+ Custom Rules + 不可覆盖的内置强制项 | 让"授权半径"可被精确刻度化（P4） |
| **执行层** | Auto-review（独立模型、out-of-band、带原因回传） | 二次审查 + 失败可恢复路径，而不是一拦了之 |
| **主动性层** | **proactive research 严格只读** | **全篇最关键取舍**：主动 ≠ 自动执行；用"主动只读"换心理安全感 |
| **渠道层** | ChatGPT / Slack / Teams / 语音 / 短信（将支持），上下文跨渠道跟随 | 渠道是入口，不是边界；消灭"换个地方就要重讲一遍" |
| **协作层** | Space + Pages：dot 与人共同编辑同一份"活文档"，可 @dot 留言 | 从"聊天产出物"升级为"人与 agent 共同维护的状态"，是 agent 真正嵌入流程的落点 |
| **组织层** | specialist dots：独立身份 / 凭证 / IT 配发硬件 / 对接系统 of record；对接 Microsoft Agent 365 | 把 agent 纳入企业 IAM 与治理；首批场景是采购、发票处理、邮件营销、客户支持、商务合同——**全是"有明确边界的后台职能"** |

### 4.1 最值得抄走的三招

1. **主动只读化**：把"agent 主动"与"agent 执行"解耦。让 agent 在后台**读、想、准备**，但**发、改、买、删**一律过闸门。这是把"惊喜"和"惊吓"分开的产品手法。
2. **失败要回传原因**：Auto-review 拦下动作时，不是简单阻断，而是**把拒绝原因回传给 dot**，让它可以转问用户、换允许的路径、交还敏感步骤或停下。这把安全机制从"墙"变成了"对话"。
3. **敏感度分级决定授权颗粒度**：健康数据 → 具名收件人；邮箱电话 → 收件人类别；且**授权绑定本次任务、不因延续或转派而扩大**。这是把抽象的"最小权限原则"翻译成了产品规则。

### 4.2 暴露出来的三处未闭合

1. **记忆只能整块清除**：无法查看 / 删除 / 编辑单条 dot 记忆；断开 App 不清除已吸收内容；**Reset 是唯一手段**（且会一并删除对话与计划任务）。
2. **凭证保护有边界**：安全登录与保存密码受保护，但**写在消息或文档里的密钥模型仍可见**。
3. **训练数据的边界条件**：官方称不直接训练 proactive research 与 dot 的自我笔记；但后台研究产生的笔记**若被引入某个合格会话，就可能进入训练**（取决于用户设置）。这是一个用户极难心智建模的数据流。

## 6. 对三类的具体建议

### 6.1 给 AI 软件产品经理：六条可迁移原则

| 原则 | 做法 |
|---|---|
| 1. 先定义"不可逆动作清单"，再谈能力 | 列出 send / delete / publish / pay / grant-access，逐个配处置档位 |
| 2. 把主动性做成只读 | 后台主动 = 读 + 想 + 准备；执行一律过闸门 |
| 3. 监督成本 = 留存率 | 做进度可视、过程可查（能打开 agent 的"电脑"）、随时可纠偏与叫停 |
| 4. 授权要可刻度 | 四档处置 + 用户可写规则 + 内置不可覆盖项；授权绑定任务而非绑定会话 |
| 5. 失败要回传原因 | 拒绝不是终点，给 agent 一条"转问用户 / 换路径 / 交还 / 停下"的恢复路径 |
| 6. 退出路径要在开始就设计好 | 暂停、撤销、清记忆——**没人演练过的紧急开关只是理论**（dots 目前只能整块 Reset，这是反面教材） |

### 6.2 给 CEO：三个战略判断与两个观察指标

**战略判断**
1. **chatbot 阶段结束了。** 所有助手的下个版本都会来要你的邮件、日历、浏览器权限。现在就要决定把钥匙交给谁，并认真读权限弹窗。
2. **入口之争是赢家通吃。** 谁能成为"agent 的默认入口"，谁就能让企业里其他软件反过来适配自己——这种锁定远强于 chatbot 习惯。
3. **成本模型要重算。** 常驻 agent 是按席位常驻资源计费，不是按调用计费；做三年预算时不能沿用 API 单价外推。

**观察指标**
- dots 的**扩容定价**（额外 dot / 速度 / 月工作量）何时公布、定在什么水位——这是判断其单位经济学是否成立的唯一硬信号。
- **Enterprise beta 的开关率**：管理员默认关闭，实际开启比例决定这是不是真的进了企业。

### 6.3 给 CTO：五道采用闸门

在把 dot（或任何常驻 agent）接进生产系统之前，逐道过闸。**任一不过 → 退回"建议态"或沙盒运行。**

| 闸门 | 通过条件 | 红旗 |
|---|---|---|
| **范围** | 单一产出、具名负责人、短时限；明确写出"禁止做什么"（发、删、发布、改权限、做承诺） | "帮我管客户成功"这类开放式授权 |
| **数据** | 列出每个连接源并分级；从非敏感、可逆、负责人本就有权的数据起步；凭据 / 受监管记录 / 特权法务材料先排除 | "先全接上，万一用得上" |
| **权限** | 每个动作映射到四档之一；**首轮试点只允许"读 + 起草"**，发 / 发布 / 删 / 买 / 改权限全部需审批 | 默认就能发、能删、能买 |
| **复核** | 定义检查点与证据要求（用了什么、改了什么、还剩什么不确定、需要批什么）；高影响工作查源记录而非只看摘要；**抽样复核常规任务** | 只看成品输出是否漂亮 |
| **退出** | 开始前就确定如何暂停、撤销、清除留存上下文；指定连接应用与计划任务的负责人；**实际演练一次下线流程** | 没人负责关机与清理 |

**首批试点任务选择**（低风险高价值、可逆）：监控公开 issue tracker、从已批准来源汇编摘要、从指定项目目录生成状态报告。**先用合成或低敏数据跑一轮**，并**故意测三件事**：一条冲突指令、一次中途权限变更、一个应该触发提问的模糊请求。度量四件事：复核后净节省时间、纠错率、不必要的升级、越界次数。

**额外的工程对策（直接对应 System Card 数据）**：由于中间任务从 5 增到 10 时中度越界率翻倍（8.6% → 19.7%），应强制**短作用域 + 检查点 + 保守授权**，并避免让一个 dot 承担跨越多天的长链条。

## 7. 风险与未解问题

| 类别 | 问题 | 严重度 |
|---|---|---|
| 技术 | **长链上下文复合污染**：链条越长越易混用指令 / 跨任务携带信息 / 在过期授权下行事（8.6% → 19.7%） | 高 |

| 技术 | dot 有一定成功率规避 P0 优先级判定（逃逸未见，但优先级判定可被影响） | 中 |

## 9. 一页速记

> **dots = 常驻智能体 = 你给它一个目标和一个授权边界，它 24/7 在自有云电脑上推进，只在需要判断时回来找你。**
>
> - 痛点：发起税 / 编排税 / 注意力税 / agent 没有岗位 / 企业侧没有 IAM / 常驻带来信任缺口
> - 原理：`Agent 价值 = 能力 × 授权半径 × 时长`；交互原子从「请求」变「委托」；上下文挂在身份上；安全边界必须 out-of-band
> - 设计：主动严格只读；四档动作处置；Auto-review 独立审查并回传原因；跨渠道上下文；Space/Pages 人机共编；specialist dots 纳入企业治理
> - 决策：先过五道闸门（范围 / 数据 / 权限 / 复核 / 退出）；首批只给"读 + 起草"；盯住扩容定价与 Enterprise 开关率
