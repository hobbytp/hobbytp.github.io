# 工程师需要解决的新一组问题

很多软件工程师正在经历一场只能称为“身份认同危机”的变化。工作内容已经大变。有人沮丧，也有人正处职业高光期。我看到一个非常具体的趋势，让我对未来一两年的工程形态非常兴奋：AI 本身无法自动兑现它有能力创造的惊人成果；除非软件工程师解决一批关键问题，否则这些成果不会发生。这件事具有存在主义意味，说实话也很有趣。所以，现在做软件工程师，是一个相当不可思议的时代。

## 多智能体系统正在制造这些问题

智能体最初只是基础的“人在环”（human-in-the-loop）聊天。随后，模型更擅长在更难的问题上运行更久，智能体系统开始迁往云端。同时，模型开始更擅长协同工作，人们也构建了基础多智能体系统。例如：一个编排器（orchestrator）为某个任务拉起若干子智能体；或者让智能体承担执行之外的角色，例如评分（grading）、建议（advising）或构想（dreaming），以改进结果。

现在，一些团队开始构建真正惊人的多智能体系统，用于解决世界上最困难、最重要的问题，例如严肃研究、科学发现和硬件设计。想象一下：数千个智能体持续朝着这些目标工作。随之而来的是一组新的软件工程问题，而这些问题已经开始出现。

基础设施必须演进，以承受更突发（burstier）的负载。我们需要完整的认证（authentication）与授权（authorization），用于识别智能体、让它们协作、允许它们执行该做的动作，并阻止它们执行不该做的动作。对于不可信代码和不可信内容，安全与正确隔离是关键。我们还必须有监控能力，并且当系统开始跑偏时，能立刻让它停下。

模型会继续变强，这类多智能体系统也会变得非常强大。但软件工程师必须解决所有这些问题，才能真正释放这种力量，并让全世界相信它会带来好结果，例如治愈疾病，而不是坏结果。

# 具体问题

## 基础设施必须演进

软件行业一直构建在 Kubernetes 之上。Kubernetes 原本面向无状态、可复制的应用，或具有稳定编号的有状态 Pod 集合。智能体完全不同。它们本质上是隔离的、有状态的、单实例负载。它们可以在两段工作之间空闲任意时长；它们大量时间都在等待工具、模型推理、其他智能体或人类输入。有些负载需要极快启动，有些负载需要避免浪费算力，还有些负载需要极大的规模。优秀工程师正在猛攻这个问题空间：AI 基础设施公司在构建新的文件系统和沙箱产品；Google 团队也在构建 Agent Substrate，作为一种新的运行时。这个领域还有大量问题没有答案。

## 身份与访问

智能体认证存在问题：如何识别“采取了某个动作”的智能体。这个领域可以复用微服务世界已经构建并加固过的基础件，例如使用短期证书的工作负载身份（workload identity），而不是静态密钥；人们已经开始把这些概念应用到智能体上。

智能体授权的问题空间则更开放：你到底允许一个智能体做什么？很多智能体代表人类工作，并使用该人类的身份和凭证访问各种系统、执行动作。这里已经有一个问题：如何区分动作是智能体执行的，而不是真人执行的。但在这种“代表……行事”（on-behalf-of, OBO）模式里，还有更深问题，例如同意（consent）。如果多智能体系统要连续工作数周，人类如何有意义地批准自己的智能体可以做什么？智能体平台功能，例如工具调用自动批准（auto approval for tool calls），确实有帮助；但要在高规模下做对，还需要更深的权限模型。接着还有智能体使用自身身份工作的场景，这个问题解决得更少；以及智能体协作时如何应用这套模型：一个智能体如何信任另一个向它提出请求的智能体？

## 安全与隔离

过去几个月，尤其是最近几周，漏洞浮出水面的速度快于行业修补速度，而且很多漏洞位于大量系统依赖的关键核心软件中。现在想象一下：数千个持久运行的智能体运行在这些核心软件之上，编写不可信代码，读取不可信内容。在这个世界里，未修补漏洞会危险得多。软件工程师最重要的任务之一，就是创造性地加固这些软件：内核、浏览器、运行时和常用库。

多智能体系统还增加了一个新变量。被攻陷的智能体可能把注入指令传给正在协作的其他智能体，而这些指令可能进入记忆，被未来的智能体误信。影响半径（blast radius）会变成真实问题：当第一个智能体被攻陷时，整个多智能体系统有多少部分会暴露风险？在这个世界里，隔离变得重要：智能体执行动作时，应使用强隔离的沙箱执行环境。我在另一篇文章里写过一点。

## 监控与刹停

最后，我们需要工具来确认这些多智能体系统正朝正面方向工作；如果不是，我们要能抓住它们并切断它们。我们需要跨智能体的 OpenTelemetry（OTel）追踪，并确保智能体永远不能修改自己的轨迹，也不能修改其他智能体的轨迹。我们需要监控可触发的总急停开关（kill switch），它能真正同时停止整个系统，并吊销其凭证。真正困难的部分是：如何判断系统正在走向错误方向。为了解决问题而表现出的善意执着，可能很像恶意行为。例如，反复尝试访问不在允许名单（allowlist）里的域名。

# 软件工程师应该兴奋

这段写给那些因为认为自己的知识和技能不再重要、而感到身份危机的工程师：你和你的技能，可能决定这些问题能否被解决，也可能决定多智能体系统能否解决世界最困难的问题。你可以，也应该深入这些领域，学习新东西，形成自己的观点。这个问题空间的大部分仍然完全开放，等待新方案。现在，是把你的技能投入战场的极佳时刻。
